================================================================================
                    ZETU STUDIO BOOKING SYSTEM
================================================================================

A studio booking platform: calendar scheduling, slot availability, accounts
and an admin panel.

QUICK START
================================================================================

1. Open PowerShell in the "Zetu Studios" folder
2. Run: npm install
3. Run: npm start
4. Open: http://localhost:5000
5. Sign in as the super admin: zetustudios@shopzetu.com
   (its password is printed once, in a box, on the very first start)
   or the demo admin: admin@zetustudio.com / admin123

Then run "npm test" to confirm everything passes (77 tests), and
"npm run doctor" to check the database for inconsistent data.

Full walkthrough: START_HERE.md

FEATURES
================================================================================

CLIENTS:
- Book 2-hour slots, half days or full days
- View their own bookings, split into upcoming and past
- Cancel their own bookings
- Responsive layout, keyboard accessible

ADMINS:
- Everything clients can do
- See every booking with the client's contact details
- Filter by upcoming / past / all
- Cancel any booking
- Statistics: total, upcoming, this month, unique clients, top shoot type

SUPER ADMIN (zetustudios@shopzetu.com):
- Everything admins can do
- Users tab: see every account and its booking count
- Promote staff to admin, demote them again
- Remove accounts (their bookings go too)
- Cannot be demoted or deleted by anyone
- Receives every email notification

EMAIL NOTIFICATIONS -> zetustudios@shopzetu.com:
- New booking created
- Booking cancelled
- Daily schedule digest each morning (07:00 by default)
- Never block or break a booking if the mail server is down
- Configure the four SMTP_* values in .env, then: npm run mail:test

TECHNOLOGY
================================================================================

Frontend: HTML5, CSS3, vanilla ES6+ (no framework, no build step)
Backend:  Node.js 18+, Express, SQLite3, bcrypt, jsonwebtoken
Tests:    node:test (built in — no test framework dependency)

API ENDPOINTS
================================================================================

Authentication:
  POST   /api/auth/register            Create account
  POST   /api/auth/login               Sign in (rate limited)
  GET    /api/auth/me                  Current user
  POST   /api/auth/change-password     Change own password

Bookings:
  GET    /api/bookings/date/:date                 Bookings on a date
  GET    /api/bookings/calendar/:month/:year      Month occupancy
  POST   /api/bookings                            Create (409 if overlapping)
  GET    /api/bookings/my-bookings                Own bookings
  GET    /api/bookings/admin/all                  All bookings (admin)
  GET    /api/bookings/admin/stats                Statistics (admin)
  DELETE /api/bookings/:id                        Cancel (owner or admin)

Users (super admin only):
  GET    /api/users                    Every account + booking counts
  PATCH  /api/users/:id/role           Set role to client or admin
  DELETE /api/users/:id                Remove account and its bookings

Other:
  GET    /api/health                   Process + database health
  GET    /api/config                   Slot definitions and limits
  GET    /api/mail/status              SMTP state (super admin)
  POST   /api/mail/digest              Send today's digest (super admin)

SECURITY
================================================================================

- bcrypt password hashing
- JWT tokens with expiry
- Refuses to start in production with the default JWT_SECRET
- Sign-in rate limited per IP; responses do not reveal whether an email exists
- Server-side validation of every input
- Role checks enforced server-side
- Parameterised SQL
- DOM output escaped via textContent
- Security headers on every response
- Role hierarchy enforced server-side (client < admin < superadmin)
- The super admin cannot be demoted or deleted, and the role cannot be
  granted through the API

Known limitations are listed in README.md under "Known limitations".

CONFIGURATION
================================================================================

Copy .env.example to .env and edit. Every variable is documented there and in
DEPLOYMENT.md.

Customisable in code:
  Working hours / slots  -> public/js/constants.js
  Shoot types            -> public/js/constants.js
  Field length limits    -> public/js/constants.js
  Colours and branding   -> public/css/variables.css

public/js/constants.js is shared: the browser loads it as a script and the
server requires the same file, so the two cannot disagree.

TROUBLESHOOTING
================================================================================

npm: command not found        -> Install Node.js 18+ from https://nodejs.org
Port 5000 already in use      -> $env:PORT=3001; npm start
"Cannot reach the server"     -> The server is not running; npm start
Database won't start          -> Delete data/zetu.db and restart (loses data)
Frontend errors               -> Browser console (F12)
Server errors                 -> The PowerShell window running npm start

More in START_HERE.md.
